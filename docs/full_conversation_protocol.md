# 完整会话：默认工程优化验证

本方案于 2026-10-17T18:07:50Z 确定，研究 baseline 与 exact 在长会话中的表现，重点检查多次索引重建。此前包含 fused 的长会话计划调整为这两组；fused/joint 的结构化输出另见独立会话实验。九次主实验仍按原方案执行。

## 数据与配置

使用 LoCoMo sample 0 / conv-26 的完整会话，预计 419 条记录。启动前核对记录数与内容校验值。问题从类别 1–4 中轮转选取，要求标注依据非空且全部出现在已加载记录内，最多 48 题；候选不足时全部纳入。保存原始问题下标和类别分布。本案例包含一个会话、一次重复。

baseline → exact 依次各运行一次。每组从空记忆图和独立空响应缓存开始，运行前重置服务端前缀缓存。共同配置：

- Qwen3-8B BF16、固定版本 MiniLM；temperature=0、seed=42、max_tokens=2000、RP=1.05。
- tag_budget=16、tag_budget_policy=observe，QA context=upstream。
- retrieve-k=10、evo-threshold=100、笔记信息 workers=4、prefetch-window=16。
- 关闭结构化输出；保存源码快照、命令和模型版本。

## 记录与回放

保存构建和 QA 时间、实际请求数、输入/输出 tokens、标签超限次数、各阶段耗时、索引重建次数及逐题得分。用 baseline 响应驱动 exact，逐条比较记忆状态、请求键和 QA；exact 也从自己的响应回放。回放要求零 HTTP。

每组最多尝试一次。普通推理失败时保存进度与错误，继续尚未尝试的另一组；源码、配置或回放不一致时停止实验。速度和质量使用同一案例中两组都完成的结果计算；单组完成时单独报告。

保存 GPU2 监控，沿用主实验的显存稳定筛选规则。共享 GPU 的计算竞争仍可能影响计时。
