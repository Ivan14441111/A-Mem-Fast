# 联合策略：128 条记忆的扩展计划

预设时间为 2026-10-17T18:18:11Z，早于三项结构化检查和 joint 实时输出。本方案延长同两个独立测试会话的输入前缀，与 64 条实验共享部分题目。

## 样本与配置

sample 3 / conv-42、sample 4 / conv-43 各取时间顺序前 128 条记录。问题限类别 1–4，要求标注依据非空且全部位于已加载前缀，按类别轮转各取 24 题；候选分别为 28 和 31 题。选中类别计数为 `{1:4, 2:7, 3:3, 4:10}` 与 `{1:2, 2:5, 3:4, 4:13}`。

每会话重复两次，共四轮、48 道独立题。其中包含 64 条的全部 31 题，新增 17 题；两种长度合计为 48 题。

A=baseline，B=exact，C=structured fused，D=structured joint。顺序沿用 sample3r1 A-B-D-C、sample3r2 C-D-B-A、sample4r1 B-C-A-D、sample4r2 D-A-C-B。每组从空图和独立空响应缓存开始，运行前重置前缀缓存。每轮安排 baseline→exact 以及 exact/fused/joint 自身的零 HTTP 回放；因中止而跳过的回放可在事后使用已有缓存完成。

沿用 64 条开始前确定的模型、模板、通用 schema 和服务配置：Qwen3-8B、固定版本 MiniLM、temperature=0、seed=42、max_tokens=2000、RP=1.05、tag16/observe；仅 fused/joint 的 JSON 阶段启用结构约束。QA context=upstream、retrieve-k=10、evo-threshold=100、workers=4、window=16。模型与 schema 已预热，空响应缓存构建的时间单独记录。

## 启动条件

先完成九次主实验及回放、三个固定图的上下文去重、结构化实现和三项格式检查、默认完整 419 条案例、64 条 structured 实验。三项检查须全部通过，源码、配置及回放均须一致。

128 条的样本和配置固定，启动由以下时间条件决定：

1. 距 UTC2026-10-17 22:42 截止至少 120 分钟，即不晚于 20:42。
2. 估计运行时间不超过剩余时间减 40 分钟，预留最终验证、结果整理和文档时间。

估计结果在启动前保存为 JSON。对四个对应的 64 条轮次，分别计算每组的 `2×build_seconds + qa_seconds×24/该轮题数 + init_seconds`，再加入该轮零 HTTP 回放时间的两倍和已记录的其他固定开销，全部求和后乘 1.20。

缺少完整计时的组使用保守替代值：构建取全部已完成组的最大值，QA 取最大每题时长乘该轮题数，初始化和回放也取可用最大值。完全缺少估计依据时取消扩展。这是排期估算，实际性能仍由运行测量。

## 运行与汇总

四轮各尝试一次。普通推理失败后保留诊断并继续，源码、配置或回放不一致时停止。按组、比较和会话分别列出计划、尝试、完成、失败、未运行次数；速度与质量使用完成配对。

报告构建和构建+QA 时间、tokens、HTTP、完成率、标签超限、分支、索引重建次数和逐题得分。先平均会话内重复，再等权汇总两个会话；速度采用配对比值的几何平均。两种长度同时改变已知事实、图和检索候选，题目变化需结合这些因素解释。研究规模为两个会话、48 题。
